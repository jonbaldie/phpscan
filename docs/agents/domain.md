# Domain documentation

This repository has one domain context. When present, read root `GLOSSARY.md`
and the relevant decisions in `docs/adr/` before exploring or naming concepts.
Use their vocabulary in issues, test names, and proposals. Surface a conflicting
ADR explicitly before changing its decision.

If these files are absent, proceed. Add a glossary or ADR when work actually
resolves a term or decision; their absence is not a setup failure.
The extraction and distribution rationale is in
[release design](../release-design.md).
